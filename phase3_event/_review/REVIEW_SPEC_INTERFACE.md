## 0. 一句话结论

SPEC 现在**不能直接拿去实现**。它把"接口"写成了"函数签名 + 一句口号"，而这些口号里有 **至少 5 条会直接产出错误的数**、**9 条验收测试在正确实现上必然失败或在错误实现上必然通过**。最致命的三条：

- `block_weights` / `boot_se` 的维度在 block=48 时**自相矛盾**，写不出一个同时满足签名和验收的实现（P1）；
- `six_cell_design` 在事件子样本上**秩为 4（列数 6）**，而 GUIDANCE 的实验 3、4 恰好只用事件子样本（P3）；
- `cross_sectional_demean` 的验收条件**只有在"用被检验的样本自己去均值"时才成立**——也就是验收测试在主动挑选那个错误实现（P5）。实测两条路径的 DiD 差 44%、水平差 140bp。

## 1. `block_weights` + `boot_se`：面板 block bootstrap 的接口是坏的

### P1-A（致命）维度不自洽，block=48 时签名与验收互斥

**问题**
```
block_weights(hours_sorted, block=48, reps=1000, seed=...) -> np.ndarray
    语义：reps × n_blocks 的重抽权重矩阵，供对"按小时可加"的统计量加权
    验收：权重之和每行必须等于 n_blocks
boot_se(per_hour_sums, per_hour_counts, weights) -> float
```

**为什么是问题**
- `weights` 的形状是 `(reps, n_blocks)`，`boot_se` 吃的是 `per_hour_*`。这两个长度相等**当且仅当 n_blocks == n_hours，即 block=1**。实测 headline 事件落在 **35,998 个不同小时**上（其中 h=24 有结局的 255,807 行落在 35,974 个），block=48 时 `n_blocks` 是 749（观测小时）/ 822（事件跨度）/ 867（ok 池），**没有一个是 35,974**。所以：
  - 若 `weights` 真是 per-block，`boot_se(per_hour_sums, ...)` 无法调用（`(1000,749) @ (35974,)` 报错），只能由调用方**先把小时加总成块**——但契约没写这件事，`hours_sorted` 就成了"只用来数 T"的死参数，块边界规则被藏进实现里。
  - 若 `weights` 是 per-hour（"按小时可加的统计量做加权"这句的字面意思），形状必须是 `(reps, n_hours)`，每行和是 `n_hours`，于是**验收条件"每行和 = n_blocks"只在 block=1 时通过**。把验收测试按 block=48 跑，它和语义要求互相打脸。
- 参数名 `hours_sorted` 还在暗示"逐行排好序的 hour 列"。实测 headline 有 255,807 行、35,974 个不同小时；若实现者把行级 hour 数组传进去，`n_blocks = 255807//48 = 5,329`，权重会按**行**而非按小时施加，同一小时内各合约的相关性当场被破坏——正是用户担心的那个失败模式，而且**验收测试照样通过**（每行和仍等于 n_blocks）。

**建议怎么改**（三选一，推荐 A）
```python
# A. 显式携带 hour -> block 映射，权重按"块多重度"给，块内所有小时同权
def block_map(n_hours: int, block: int) -> np.ndarray            # (n_hours,) int, 0..n_blocks-1，按【日历小时】切，不是按观测行切
def block_draws(n_blocks: int, reps: int, seed: int, kind="moving"|"circular"|"fixed") -> np.ndarray   # (reps, n_blocks) int8 多重度

def boot_replicates(stat, hour_codes, block, reps, seed) -> np.ndarray  # (reps,)
    """stat(hour_index) -> float；hour_index 是重抽后的小时索引数组（可重复、可缺）"""
```
并在契约里写死三句话：
1. **块定义在全局日历上**：`hour_codes` 必须是 `0..T-1` 的稠密日历编码（含无观测的小时），这样块长 48 才是 48 个真实小时；
2. **一次抽中的块把该 48 小时内所有合约的所有行整体带走**；
3. **`hours_sorted` 必换成 `n_hours`（标量）**，或在函数首行 `assert np.all(np.diff(hours_sorted) > 0)`。

> 顺带，这条不是理论问题：ok 池本身是连续的（41,615 个有观测小时，min 2 / max 41,616，跨度正好 41,615，无空洞），所以"按观测行切"和"按日历切"在 ok 池上等价；但 headline 事件只落在其中 35,998 个，**在事件子样本上按观测行排序切块，一个块内就是 48 个不相邻的小时**，把要保的相关性自己拆散了。实测：同一统计量、同样 block=48，"按观测行切"给 1.04×（原始）/ 1.30×（中性），"按日历切"给 1.11× / 1.33× —— **仅块边界规则之差就是 7% 的 SE**，而两种实现都能自称合规。

### P1-B（致命）"moving-block" 在 `(reps, n_blocks)` 形状下表达不出来

**问题** D13 冻结的是"**48h moving-block** bootstrap"。moving-block 的块起点是 `T-L+1` 个重叠位置，每个小时被最多 L 个块覆盖，权重要除以覆盖数，且**每行权重和不是常数**。`reps × n_blocks` + "每行和 = n_blocks" 描述的只能是**不重叠分块 / circular block**。

**为什么是问题** 这不是措辞问题：两种方案的有限样本性质不同（moving-block 对块边界偏差更稳），而 D13 是"先改 DECISIONS 再改代码"的冻结口径。现在的 SPEC 让人**违反 D13 却通过全部验收**。

**建议** 契约里二选一并写死 `kind`；若是 moving-block，把返回值改成 `(reps, n_hours)` 的覆盖计数矩阵 `cov`，`boot_se` 用 `cov @ hourly_contribution / cov.sum(1)` 自归一。顺带把"最后不足 48 小时的尾巴"（35,974 = 749×48 + 22）怎么处理写进契约——丢掉 22 小时还是并入最后一块，会影响 0.06% 的样本，属于必须留痕的口径。

### P1-C（致命）重抽维度选错了：真正的依赖在合约维度，不在小时维度

**问题** `boot_se(per_hour_sums, per_hour_counts, weights)` 在接口层面**只允许**按小时聚类。契约里没有任何位置放合约维度。

**为什么是问题**（以下全部实测，headline，h=24，R1−R4 DiD）
| 度量 | 原始收益 | 市场中性收益 |
|---|---|---|
| 按小时聚类 SE 的 t | −2.79 | +0.77 |
| 按**合约**聚类 SE | **0.60×** 小时 SE（t=−4.66） | **1.35×** 小时 SE（t=+0.57） |
| 双向（hour×symbol, CGM）SE | 1.07× | **1.40×** |
| 不重叠块 L=48（按日历切） | 1.11× | **1.33×** |
| 不重叠块 L=48（按观测行切） | 1.04× | 1.30× |
| 不重叠块 L=24 / L=96 | 1.09× / 1.05× | 1.26× / 1.36× |

- 市场中性化之后，**小时维度的序列相关几乎消失了**：hourly influence 的 ACF 在 lag 1..6 是 `0.066, 0.049, 0.035, 0.032, 0.024, 0.015`，**lag 24 = 0.001**。也就是说"24h 重叠窗口 ⇒ 必须 block bootstrap"这个前提，在**扣掉截面均值之后就基本不成立了**——因为重叠的那部分正是共同因子，去均值把它一起去掉了。
- 真正剩下的是**合约维度**：同一合约相邻小时的 24h 窗口互相重叠、且合约有持久异质性。按合约聚类把 SE 放大 1.35×，而 block bootstrap 抓不到。
- 结论：**block=48 的成本换来的修正只有 1.1–1.3×，而漏掉的合约维度有 1.35–1.40×。**

**建议** 契约新增 `two_way_se(...)` 或要求所有确认性表**同时报 hour-cluster、symbol-cluster、two-way 三个 SE**，判定用 two-way。这需要改 D13 第 129 行那一格（"按时间块重抽，不按行"→"按 (小时, 合约) 双向重抽或 CGM 复合"）。**这是本次评审唯一一条要求动 D13 的**，其余都在 SPEC 内部可解。

### P1-D `boot_se` 返回 `float`，导致实验 1 的等价性检验根本做不出来

**问题** 实验 1 的判定是"OI 维度 + 交互这 **4 个系数的 95% 区间全部落在 ±10bp 内**"，实验 4 是"六个斜率是否相等（χ²(5)）"。这两件事都需要**联合分布**（4 维 / 6 维在同一个概率空间上的重抽向量）。`boot_se -> float` 只给你每个标量的 SE，你无法把 SE 相加，也无法构造联合区间；每个实验只能各自重跑一遍 bootstrap。

**建议** 把返回值从"SE"改成"重抽分布"：
```python
def boot_replicates(stat, ...) -> np.ndarray   # (reps,)；stat 返回标量或定长向量
```
SE、百分位区间、Holm 的 p、4 维联合区间全部由调用方从同一组 `reps` 里算。这一改动同时解决 P4 和 §6 的性能问题，是本次评审性价比最高的一条。

### P1-E 验收条件本身是错的（不是过严，是不可达）

> "必须 ≥ 按 hour 独立聚类的标准误（实测 R1 的 t 从 3.96 掉到 1.90，即 SE 至少放大 1.5 倍）"

**为什么是问题**
1. **两个锚互相矛盾**：3.96/1.90 = **2.08×**，不是 1.5×。
2. **1.5× 在这份数据上不可达**：正确的 block bootstrap 实测只给 1.05–1.36×（上表）。要凑到 1.5× 只能靠实现错误——比如漏掉覆盖数归一（我第一版探针就这么干，得到 7.7×）、或把块当独立样本。
3. **不等式方向在单个实现上不成立**：block SE ≥ cluster SE 是期望意义下的，不是每次抽样都成立；用一次实现去判"必须 ≥ 1.5"是拿一个随机量当门槛。
4. **循环论证**：门槛来自 v1 的 3.96/1.90，而 D13 说 v1 的 t 全部虚高、正是要被替换的东西。**用被替换品当验收基准**。

**建议** 删掉这条，换成两条真能失败的测试：
- **构造性 DGP 测试**：造一个已知块内相关结构的面板（例：100 合约 × 200 小时，`y_it = u_{⌊t/48⌋} + e_it`，已知真 SE），断言 `boot_se` 与解析 SE 的相对误差 < 10%。这个测试只有对的实现能过。
- **结构不变性测试**：把同一小时里所有合约的 y 加上一个任意大的公共冲击，`boot_se` **必须不变**（1e-12）。这条直接检验"没有破坏同一小时内各合约的相关性"，是用户问题的正面回答，而现在的契约一条都没有。

## 2. `boot_median_se`：允许子抽样 = 允许一个有偏的估计量，且验收只查耗时

### P2-A（致命）子抽样引入的偏差不是"写进 docstring"就能免责的

**问题** `boot_median_se(values, hour_codes, block=48, reps=200)`，验收 = `单次调用 < 3 分钟` + `docstring 写明做法与偏差方向`。

**为什么是问题**
- **行级子抽样 → SE 系统性偏小**（子样本内破坏了小时内的合约相关），偏差方向随子抽样比例变化，不可符号化；
- **块级子抽样 → SE 系统性偏大**（有效块数从 749 掉到 m，`√(749/m)` 倍）；
- 两种做法的偏差方向相反，而验收只要求"写明方向"——**这句话的意思是"实现者可以自选一个有偏估计量，只要诚实"**。这不是契约。
- `reps=200` 与 D13 冻结的 1000 直接冲突，也让中位数区间与均值区间不是同一次重抽出来的，二者的对比（GUIDANCE 所谓的"本阶段最重要的矛盾"）失去可比性。

### P2-B 分位数上的 block bootstrap 本身就不一致

**理论** 分位数是经验分布的非光滑泛函，block bootstrap 在相依数据下**对分位数不一致**（Edgeworth 展开在 `√n` 阶失效；这也是 subsampling 被提出来的原始动机，Politis–Romano）。所以即便 `reps=1000`、不子抽样，`boot_median_se` 的覆盖率也是错的——它给的是一个**收敛更慢**的区间。SPEC 把一个统计上已知有问题的方法写成默认接口，且不为它设任何可检验的门槛。

### P2-C 更根本的：实验 2 的估计量在契约里不存在

**问题** GUIDANCE 实验 2 要的是"同六格模型，取**中位数版的双重差分**"。而 `boot_median_se(values, ...)` 只是"某个向量的中位数的 SE"——**它不知道什么叫双重差分**。

"中位数版 DiD"至少有三种互不相等的定义：
1. `median(y|R1) − median(y|R4)`（差的中学数，**不是任何处理效应**，它主要由两格的**水平**决定）；
2. `median(y|R1−R4)`（需要配对，数据里没有配对）；
3. 分位数回归在 τ=0.5 上的 DiD 系数（**这才是与 OLS 系数可比的量**）。

三者的数值完全可能不同号。GUIDANCE 那个 −0.454pp / 区间 [−0.62,−0.31] / "1000 次全负" 的口径，从 SPEC 里**推不出来是哪一个**，而 `六格设计矩阵` 只有 OLS 一条路径（`ols_boot`），没有任何中位数/分位数的设计矩阵接口。

**建议**
1. 删掉 `boot_median_se`，改成 **`boot_cell_medians(df, y_col, cell_col, ...) -> (reps, n_cells)`**：在每次重抽里重算 6 个格中位数（**实测 1000 次全样本中位数重抽只要 5.9 秒**，子抽样完全没必要），再让调用方组合成任何非线性泛函。这样"中位数版 DiD"的定义被显式写在调用处，而不是藏在函数里。
2. 若要一个**有渐近保证**的中位数 DiD，用 **τ=0.5 的分位数回归**，并在重抽里重估（QR 不能靠充分统计量，6 列 × 1.38M 行 × 1000 次是分钟量级的量级估计、**未实测**；可用 6 个格中位数的重抽结果做初值，把迭代次数压到个位数）。契约里应给出这条路径而不是"随便你怎么抽"。
3. 无论走哪条，**均值与中位数必须用同一组重抽权重**（同 `seed`、同 `block`、同 `reps`），否则两者的"符号矛盾"里混进了两次不同的抽样噪声。

## 3. `six_cell_design`：q 与 q² 不正交，而且**在实验 3/4 的样本上秩亏**

### P3-A（致命）事件子样本上 `q² ≡ 1`，设计矩阵秩 4 / 6

**问题** 事件的定义是"价格和 OI **都**超阈"，所以在事件行上 `q ∈ {−1,+1}`，于是 `q² ≡ 1`、`P·q² ≡ P`。

**实测**（R1..R4 四行）
```
X6 = [[1, 1, 1, 1, 1, 1],      rank(X6) = 4   (列数 6)
      [1, 1,-1, 1,-1, 1],      q2 unique = {1.0}
      [1,-1, 1, 1,-1,-1],      corr(P, P*q2) = 1.000   ← 完全共线
      [1,-1,-1, 1, 1,-1]]
```

**为什么是问题** GUIDANCE 的实验 3（"样本：headline **事件**"）、实验 4（"样本：headline **事件**"，"六格各估一个斜率"）都只喂事件行。此时：
- `np.linalg.lstsq` **不报错**，返回最小范数解，`b` 的 6 个分量按 SVD 任意分摊，**没有一个是可解释的**；
- 两条验收（"列名 = const,P,q,q2,Pq,Pq2"、"任一行必须且只能落在一格里"）**全部通过**；
- 实验 3 声称的 χ²(4) 实际只有 4 个可识别方向（其中"OI 维度"只剩 1 df），实验 4 的"χ²(5) 六斜率相等"更是不可能——6 个斜率里 2 个不存在。
- GUIDANCE 记录 χ²(4)=1165 / χ²(5)=69.7。**这两个数用现在的契约复现不出来**，除非把 OI 安静的对照行也放进样本。而实验 3/4 的样本定义恰恰不含对照行。

**建议**
1. 契约里写明 `six_cell_design` 的**前置域断言**：`df` 必须同时含 `q=0` 与 `q=±1` 的行，否则抛错（不做兜底，直接抛）。并且**实验 3、4 要么把样本改成"事件 + 价格超阈/OI 安静对照"，要么改用四格（2×2）设计**——这是一个必须回 D13 确认的口径分歧，不是实现细节。
2. 验收加一条："对任一输入 `df`，`np.linalg.matrix_rank(X) == X.shape[1]`；否则报错"。这一条能在 1 秒内抓住上面这个 bug。

### P3-B q 与 q² **不**正交；"正交"这件事本身也不重要，重要的是参数化后的可解释性

**实测**（六格真实格频：R1 74,959 / R2 50,564 / R3 44,623 / R4 85,933，安静对照约 112 万）
```
corr(q, q²)   = −0.0596      ← 不为 0
corr(P, q²)   = −0.0076
corr(P, P·q²) = +0.4314      ← 交互项与主效应强相关
corr(q², P·q) = +0.2329
cond(X) = 3.0（不秩亏时数值上很良性）
```

**为什么是问题**
- `Σ q·q² = Σ q = n_up − n_down`。**正交当且仅当 OI 极端增与极端减的格频相等**。实测 headline 是 119,582 vs 136,497，差 16,915。这不是"大致正交"，这是**一个由样本构成决定的、随频率/样本/年份变化的非零相关**。用"q 和 q² 正交"来给这个编码做辩护是错的。
- 更关键：数值良性 ≠ 可解释。`q ∈ {−1,0,1}` + `q² ∈ {0,1}` 把"OI 极端"写成一个**强制对称**的二次型：q=+1 的效应是 `b_q + b_{q2}`，q=−1 是 `b_{q2} − b_q`。**两者到安静格的偏离被强制等距**。而 GUIDANCE 自己的结论是"波动上 OI 很强，且集中在'价格跌 + OI 增'那一格"——这正是不对称，它被模型结构压进了 `b_q`。所以"看 `b_q` 和 `b_{q2}` 的区间"看的是一个被旋转过的坐标系。

### P3-C "OI 维度 2df" 的检验该怎么写

**正确写法**：`span{q, q²}` 与 `span{1{q=+1}, 1{q=−1}}` 是同一个 2 维子空间（因为 `1{q=+1}=(q+q²)/2`、`1{q=−1}=(q²−q)/2`），所以**Wald 统计量对这对参数化是不变的**——只要它是用**完整协方差**算的：

```python
V  = np.cov(reps[:, [i_q, i_q2]].T)          # 来自同一组重抽，不是两个标量 SE
b  = b_full[[i_q, i_q2]]
chi2 = b @ np.linalg.inv(V) @ b              # df = 2
```

**三个必须写进契约的禁忌**：
1. **不许**写成 `t_q² + t_q2²`。那等于假设 `Cov(b_q, b_q2)=0`，而实测 corr 是 −0.0596，且交互块 corr 到 0.43。
2. **不许**用"每个系数的 95% 区间"做联合陈述。4 个独立 95% 区间在 `b` 相互独立时的联合覆盖只有 `0.95⁴ = 81.5%`；而 D13 只规定了 5 个确认性检验之间的 Holm，**没规定一个检验内部 4 个系数的多重性**。这是 D13 的空白。
3. 交互项的 2df 检验同理：`span{Pq, Pq²}` vs `span{P·1{q=+1}, P·1{q=−1}}`。

**关于实验 1 的判定规则"4 个系数全部落在 ±10bp 内"**：在 `(q,q²)` 坐标下这条是**过分保守**（充分但不必要）——格效应是 `d_U=(b_q+b_{q2})/2`、`d_D=(b_{q2}−b_q)/2`，所以 `|b_q|,|b_{q2}| ≤ 10bp ⇒ |d_U|,|d_D| ≤ 10bp`，但反过来不成立：`b_q=0, b_{q2}=19bp` 时两格各偏 9.5bp，等价性**成立**却被规则判失败。而规则本身判的是"旋转后的系数"，不是"OI 极端相对安静的效应"。**建议把等价界限直接写在格子对比上**（`d_U, d_D, e_U, e_D` 四个数），并用**同时置信域**（`√(χ²_{4,0.95})` 尺度）而不是 4 个单独的 95% 区间。

### P3-D 单位：10bp 是 0.001 还是 10？

**实测** `fwd_24h` 是 **decimal**（R1 均值 0.002235），而 GUIDANCE 正文写的是 `+0.2235`（百分数，即 22.35bp）。**同一个数在两份文档里差 100 倍**，而 SPEC 从头到尾没写 `fwd_*` 的单位。实现者写 `EQ_BOUND = 10` 再和 decimal 系数比，**所有系数一律"落在 ±10bp 内"，等价性永远成立**。这是一个一行的、结果反转的、且不会报错的 bug。

**建议** 在 `EventConfig` 加 `eq_bound_bp: float = 10.0` 与 `bp: float = 1e4`（或明确"所有统计量以 bp 报告 = decimal × 1e4"），并在 `boot_replicates` 的 docstring 里写死返回单位。

### P3-E 价格"安静"的行在六格设计里没有位置

**问题** `six_cell_design(df, price_col, oi_col, thr_p, thr_o)` 只按 `price_change` 的**符号**定义 P，不说 `|price_change| ≥ thr_p` 是前置条件。

**为什么是问题** 实验 5（纯 OI 基线）用"全部有效行 7,010,789"，其中大量行的价格是安静的；把这些行喂进 `six_cell_design` 会被静默分到 `P=+1` 或 `P=−1` 的某一格。验收"任一行必须且只能落在一格里"**照样通过**（它确实落进了一格，只是错误的一格）。

**建议** 契约加两件事：`six_cell_design` 里 `assert (df[price_col].abs() >= df[thr_p]).all()`；以及返回**每格计数**（`cell_counts`），验收时和 §三 的 R1–R4 冻结计数对齐。这才是"落在哪一格"的可检验版本。

### P3-F 实验 1 的控制变量不在设计矩阵里

GUIDANCE 实验 1 明写"价格冲击幅度作控制"，而 `six_cell_design` 只返回 6 列、且验收要求列名**恰好**是那 6 个。`shock` 进不去。**契约与口径冲突**，要么加 1 列并改列名契约，要么明说控制变量在调用方外挂（那 `names` 就不完整，下游没法知道列序）。

## 4. `winsorize(by=...)`：按格内压平会让 DiD 变成"截尾规则的函数"

### P4-A（致命）按格压平，压平规则本身就是处理变量

**实测**（headline，h=24，市场中性超额收益，R1−R4）
| 方案 | R1 均值 | R4 均值 | DiD |
|---|---|---|---|
| 不压 | −0.000416 | −0.000646 | **+2.30 bp** |
| 全样本 1/99 压平 | −0.001174 | −0.001003 | **−1.74 bp** |
| **按格内** 1/99 压平 | −0.000916 | −0.001003 | **+0.78 bp** |

- **符号会翻**（+2.30 → −1.74），**幅度差 4bp = 等价界限 10bp 的 40%**。
- 机制很清楚：格内压平的阈值各不相同——R1 上界 0.29697，R4 上界 0.22413（**差 33%**）。R1 保住了更多右尾，R4 被砍得更狠，差值就是这么"造"出来的。
- 逐格阈值（压平前 → 后峰度）：R1 163.8→9.87（thr −0.1597/0.2970）、R2 357.3→9.75、R3 174.2→9.31、R4 994.4→8.94（thr −0.1332/0.2241）。
- 这等于**用被检验的格定义去定义截尾规则**：格 → 阈值 → 结果 → 再比格之间。格间比较的识别假设（各格只差一个水平）被这一步直接违反。

**建议**
1. **禁掉 `by` 的默认值缺失**：`by` 必须显式，且**不允许取值为"六格/regime"**（写进 docstring 的禁例）。合法值：全样本（`by=None`）、`hour`（截面内压平，可辩护）、`year`（分年稳健性）。
2. 若坚持按格压平，必须**用同一组阈值**（全样本阈值）压每一格，并把**每格被压的观测数与两端阈值**列表输出。契约里加一条验收：**"换 `by` 后 DiD 的变化 ≤ 0.5bp"** —— 我实测差 2.5–4bp，所以这条会把当前设计判失败，这正是它该做的。
3. 报告 `winsorize` **只做诊断、不进判定**（D13 已把 1%/99% 写死，就不要再让 `by` 变成第二个自由参数）。

### P4-B `winsor_fwd_*` 这一列建在**错误样本**上，实验 1 用不了

**问题** §二 把 `winsor_fwd_{h}h` 加成 **event 表**的列（923,235 行）。但实验 1 的样本是"事件 + **价格超阈 / OI 安静的对照行**（约 112 万行）"，**对照行不在事件表里**。

**为什么是问题** 于是实验 1 面临一个二元选择，两条都错：
- 对照行用**事件子样本**算出的 1%/99% 阈值压 → 阈值是"被选中的样本"的函数，而样本是按过去的冲击选的（与波动正相关），阈值内生；
- 对照行另算 → 与事件行的口径不同，**DiD 变成两套截尾规则的差**，就是 P4-A 那个 4bp 的坑换了个位置。

**建议** `winsor_fwd_*` 的阈值必须**在 ok 全样本（7,236,831 行）上一次算定、存成常量**（进 `EventConfig` 或一张小表），事件表和对照行**共用同一组阈值**。事件表里的列可以留，但契约必须写明"该列使用全样本阈值"，并加一条验收：用事件表反推出的阈值 = 全样本阈值。

### P4-C `by` 的验收测试对任何分组都成立

> "压平后峰度必须比原来小；被压的观测数约等于 lower+upper 的比例"

两条都是**构造性恒真**：任何分位数截尾都会按定义压掉 2%（每组 2%），任何截尾都会降低峰度。`by=row_id`（每组 1 个观测）——那就一个都不压、峰度不变——会失败；但 `by=symbol`、`by=year`、`by=regime` 全部通过，而这些选择之间的 DiD 差 4bp。**测试对"该压哪一组"零信息**。

**建议** 换成锚定测试：给定一个已知分位的构造向量（例 `np.arange(1000)`），断言返回值等于 `np.clip(x, 9.99, 990.0)`（1e-12）。这测的是"阈值取对了"，而现在的测试连阈值都不看。

## 5. 验收清单里哪些是"自己验自己"

按"能不能失败"分三档。

### A 类：构造性恒真，**任何**实现都通过（6 条）
| 条目 | 为什么什么都没验 |
|---|---|
| `cross_sectional_demean`："按 hour 分组，均值精确为 0（1e-12）" | 这正是"去均值"的定义。而且**只有当你用被检验的那批行自己去均值时才成立**（见下）。 |
| `block_weights`："每行权重之和 = n_blocks" | 这是"抽 n_blocks 次、每次计一个块"的定义。对 iid 分块重抽、对 circular、对漏掉覆盖归一的错误实现，全部成立。**"同一块内 48 个小时拿到同一个权重"这个唯一重要的性质完全没测。** |
| `winsorize`："峰度变小 + 被压数≈2%" | 见 P4-C。 |
| `six_cell_design`："任一行必须且只能落在一格里" | 只要 `q` 是从 `sign()` 出来的就恒成立；落进**哪**一格、秩是多少、价格安静行怎么办，全不测。 |
| `ols_boot`："SE > 0" | 任何正数都通过。 |
| `overreaction_slope`："斜率个数 = 组数；SE > 0" | 纯形状检查。 |

### B 类：达标不代表对，且**正确实现反而不达标**（3 条）
| 条目 | 问题 |
|---|---|
| `boot_se`："≥ 按 hour 聚类 SE 的 1.5 倍" | 实测正确实现只到 1.04–1.36×。**这条会逼实现者造假**（P1-E）。 |
| `winsor_fwd_24h`："峰度 < 20（原始 R1 是 111）" | 两个对象不同：列是**全事件池、去均值后**的分布，峰值 **382.9**（去均值把峰度从 220.8 抬到 382.9，因为扣掉共同因子只缩了分母没缩尾巴）。拿 R1 的 111 当基线，基线就错了 3.4 倍。压平后实测 9.55 < 20 能过，但"< 20"这个数是谁定的、为什么不是 50 或 10，没有依据。 |
| `excess_fwd_24h` 逐小时均值为 0 | 同 A 类；且实测 float32 路径的残差是 **2.2e-8**，而门槛写 **1e-12** —— **正确实现也过不去**，除非显式转 float64（`fwd_*` 存的是 float32）。契约必须写明"去均值前 cast 到 float64"。 |

### C 类：只是回归钉，不是新代码的验收
§三 的 6 条不变量（923,235 / d==0 为 0 / cont+rev+flat=1 / mdd≤0 / hit_rate==p_cont / headline⊂full）都是**对既有数据的回归保护**，对新写的 `stats_core` 覆盖率为 0。其中 `cont+rev+flat=1` 和 `hit_rate==p_cont` 是同一段归一化代码的产物，恒等式天然成立（D8/D5 已经知道这一点，照抄进验收等于把已知的恒等式当证据）。`shock ≥ 1` 同理：事件的 shock 按定义就 ≥ 1（实测 min = 1.0000000000000004），验的是定义。

### 最严重的一条：`cross_sectional_demean` 的验收**在挑选错误实现**

**实测**
- ok 池：7,236,831 行、41,615 个有观测的小时，**平均 173.9 个合约/小时**；
- headline 事件：256,079 行、35,998 个小时，**平均 7.1 个事件/小时**；
- "事件子样本自己算小时均值"与"ok 池算小时均值"的相关只有 **0.663**；用前者减出来的超额收益与用后者减出来的，**平均相差 140.8bp**（是待检验效应的 10 倍）；
- DiD 从 **+2.30bp 变成 +1.28bp**（差 44%），R1、R4 的水平各平移约 10bp；
- **而两者在"逐小时均值为 0"这条验收上：事件子样本法的残差是 3.97e-08，完全"通过"。**

所以：契约的验收条件只有在"在你要检验的那批行上做去均值"时才严格成立；用它自己规定的检验统计（ok 全截面）去均值，反而过不了这条 1e-12。**验收测试和正确的估计量方向相反。**

**建议** 验收改成锚定测试：在一个手算的 3 行 × 3 小时玩具面板上，断言 `excess[i]` 等于 `y[i] − (该小时全部行的均值)`（而"全部行"由测试显式给定，包含事件之外的行），误差 1e-12。再补一条 **`n_per_hour` 输出**：契约要求 `cross_sectional_demean` 同时返回每小时参与去均值的行数，验收断言其**中位数 ≈ 174**（不是 7）。这一条能一秒钟抓住这个 bug。

## 6. 性能上限：两个上限都松了 25–30 倍，而"松"本身是错误设计的许可证

**实测**（本机，headline，h=24，n=255,807，6 列设计，1000 次重抽）

| 做法 | 耗时 | 相对 10 分钟上限 |
|---|---|---|
| 朴素：每轮 fancy-index 255,807 行再 `lstsq` | **0.022 s/轮 → 22 s / 1000 轮** | 27× 富余 |
| 正确：小时级充分统计量（`ΣX'X`, `ΣX'y`）+ 1000 次 6×6 求解 | **0.05 s / 1000 轮** | 12,000× 富余 |
| 全样本中位数重抽（`np.median` on 255,807） | **0.006 s/轮 → 5.9 s / 1000 轮** | `boot_median_se` 上限 3 分钟 = 30× 富余 |

**为什么是问题**
1. **10 分钟的上限不构成任何架构约束**：朴素实现（每轮重算 OLS）也只要 22 秒。SPEC 说自己"不规定实现算法"，但它唯一能间接约束算法的手段（性能上限）被设成了 27× 的宽。**一个宽上限等于没有契约**，最后结果就是 8 个检验各写一遍 1000 次循环、各带一份不同的 RNG。
2. **`boot_median_se` 的 3 分钟上限和"允许子抽样"是同一件事**：因为上限松到 30×，实现者以为必须省时间，于是去子抽样，于是引入 P2-A 的偏差。**全量 1000 次只要 6 秒。这条"放宽"是完全没必要的，且它是本 SPEC 里唯一一个直接制造偏差的条款。**
3. **1000 次 × 8 个检验的真实风险不是算力，是"8 个不同的 bootstrap"**：契约没有规定同一 `reps` 组的重抽要在检验之间复用。若每个检验各自 `seed=20240501` 重抽，而样本与 `n_blocks` 不同（headline/h=1/h=24/含或不含对照行），得到的是 8 个不同的概率空间：实验 1 的 4 维联合区间做不出来（P1-D），均值与中位数的"符号矛盾"里混进了不同的抽样噪声（P2-C），Holm 的 p 值也不是同一族。

**建议** 把上限压到能逼出正确架构的水平，并写死算法骨架：
- `单个确认性检验（含 1000 次重抽）≤ 20 秒`；
- `boot_median_se ≤ 10 秒`（并**删掉子抽样条款**）；
- 契约明确：**统计量必须先塌缩成小时级充分统计量，重抽只作用于小时/块的聚合量**（这是"按小时可加"那句口号的正确落法，现在的 `boot_se` 只说了一半）；
- 契约明确：`(block, reps, seed)` 的一次抽取是**共享对象**，所有落在同一样本/同一 h 上的检验必须复用它。

## 7. 契约之外，但会立刻让实现者卡住的 4 件事

### P7-A 环境里没有 scipy / statsmodels
```
numpy 2.3.4 · pandas 2.3.3 · pyarrow 23.0.1 · scipy 缺失 · statsmodels 缺失
```
GUIDANCE 要 χ²(4)、χ²(5)、χ²(2)、χ²(3) 的临界值，实验 12/13 要分位回归的代表路径，D3 提到"双向聚类"——**这三样都需要外界包**。SPEC 没有任何依赖声明。要么在契约里指定"χ² 用 `scipy`（并写进 REPRODUCE）"，要么给一个不依赖 scipy 的 `chi2_sf`（数值上 10 行 Gamma 不完全函数即可）。

### P7-B 前向面板的 hive 分区名和列名撞车
`pq.read_table(".../forward/freq=1h/year=2021/chunk=2021-12.parquet")` 实测抛
`ArrowTypeError: Field freq has incompatible types: string vs dictionary<values=string,...>`
——分区目录 `freq=1h` 推断出的分区列 `freq` 与文件自带的 `freq` 列冲突。`pd.read_parquet` 单文件正常，`pq.read_table` / `ds.dataset(...)` 对目录直接炸。契约里没有任何"怎么读面板"的规定，而这是每个实验的第一行。

### P7-C 两套互不兼容的 `hour` 编码
- `events_1h.parquet.hour` = **自 2021-12-01 00:00 起的小时数**（实测 18067 ↔ 2023-12-23 19:00，原点精确命中）；
- 前向面板**没有 `hour` 列**，只能从 `ts_end` 推。用 epoch 小时（`ts_end//3600s`）是最自然的写法，得到 47 万量级。
- 两者对不上：我第一版探针按 `hour` 直接 join，**0 行匹配、corr=NaN，全程不报错**。

`hour_col="hour"` / `hour_codes` 这两个参数名在这个前提下是定时炸弹。**契约必须定义"hour code 是什么、原点在哪、跨表如何保证一致"**，并要求 `cross_sectional_demean` 输出 `n_per_hour` 以便一眼看出 join 是否成功。

### P7-D 参数不在 `EventConfig` 里
SPEC 说"参数从 `EventConfig` 读，脚本里不写常数"，但 `EventConfig` 实际只有 `horizons / random_draws / random_seed / bh_q / ic_min_contracts / figure_dpi`。SPEC 自带一批常数：
`block=48`、`reps=1000`、`seed=20240501`、`lower=0.01`、`upper=0.99`、`reps=200`（中位数）、以及隐含的 `eq_bound=10bp`。
其中 `seed=20240501` 与 `EventConfig.random_seed` 重复（该字段的 docstring 说的是"随机时点基准/合约内安慰剂"，语义完全不同）；`random_draws=1000` 也被同时当作 bootstrap 次数。

**建议** `EventConfig` 新增：`block_hours: int = 48`、`boot_reps: int = 1000`、`winsor_lo/hi: float = 0.01/0.99`、`eq_bound_bp: float = 10.0`、`bp_scale: float = 1e4`、`median_reps: int = 1000`。同时把 `bh_q` 的 docstring（家族 = 32）与 D13（Holm，5 个确认性）对齐——**现在这两处互相矛盾**。

### 一句话
